## What was wrong and what changed

### 1. verify.mjs reported a refused delete as a success

An MCP tool failure comes back as `isError` and does not throw, and the cleanup block in `scripts/verify.mjs` read neither the return value nor the flag. A delete refused by the divergence guard printed `ok deleted draft` and left a real draft in a real mailbox. The block now reads the result, prints FAIL and counts a failure when `isError` is set, and passes `confirmAccountSwitch: true` so the delete works wherever the try block ended.

### 2. npm test failed as root

The unwritable-log case pointed at a path under `/etc`, and `AuditLog.record` calls `mkdirSync` before it writes. As root the directory was created, no warning was emitted, the assertion failed, and a file was left outside the repository. The test now writes a regular file and uses it as a directory component, so `mkdirSync` fails with EEXIST at any privilege level. Measured on Node v22 as uid 0 and as uid 65534.

### 3. Two tools were never logged

The README says every call appends a JSON line. `guard` records only failures, each handler records its own success, and `get_active_account` and `recent_activity` had no success record. Both now call `note` before returning, and all nineteen registered tools have one.

### 4. The send confirmation hid Cc and mangled To

`send_draft` did not pass Cc to the dialog even though the draft carries it, and it split the raw To header on every comma, so `"Roberts, Dan" <dan@example.com>` became two recipients that do not exist. The same array was written to the audit log. Both the dialog and the record now use `parseAddressList`, which leaves a quoted display name intact, and both carry Cc.

### 5. search_all_accounts reported ok on a failed mailbox

A revoked token, a 403, or an identity mismatch was downgraded to a string, the result carried no `isError`, and the audit record said ok. With `merge` set, the failures were appended after the merged rows. The tool now records the outcome as an error with the labels that were not searched, sets `isError` on the result, and puts the failures before the rows.

### 6. The lapsed-selection message was unreachable

`NoActiveAccountError` takes a `lapsed` flag and both call sites passed the literal `false`, because `Session.active()` deleted an expired selection and discarded the fact that one had existed. A user whose window had closed was told no account had ever been set. `Session` now tracks the drop and exposes `didLapse()`, and both call sites pass it.

### 7. Attachment IDs are not printed

`FullMessage.attachments` carries an `attachmentId`, and the only renderer prints filename, MIME type and size. The README sentence now says filenames, types and sizes.

### 8. Two absolutes about permanent deletion

The README said the server cannot permanently delete mail and that nothing here deletes mail permanently, while `delete_draft` calls `users.drafts.delete`. Both sentences were rewritten to name `delete_draft`.

### 9. parseAllowSend does not compare against an exact string

The value is trimmed and lowercased before comparison, so `TRUE` and `True` enable sending, and `false`, `0`, `no` and an empty value are accepted as off. The README, `.env.example` and the docblock now describe that.

### 10. An empty GMAIL_CLIENT_ID blocked the GOOGLE_ fallback

`''.trim()` is not nullish, so `??` short-circuited on the empty-but-present variable that `cp .env.example .env` leaves behind. A user supplying `GOOGLE_CLIENT_ID` was told `GMAIL_CLIENT_ID` was missing. The chains in `src/accounts.ts` and `scripts/authorize.mjs` now use `||`, and `test/accounts.test.mjs` covers the empty-string shape.

### 11. popup-test did not build first

`scripts/popup-test.mjs` imports from `dist/`, which is git-ignored, and it was the one script without a build step. `package.json` now runs `npm run build` first.

### 12. Four write tools omitted the divergence flag

`recent_activity` prints DIVERGED from a field the audit record carries. `delete_draft`, `modify_labels`, `trash_thread` and `send_draft` did not set it, so a send executed out of a non-active mailbox showed no marker. All four now record it.

### 13. The tail-read comment described something the code did not do

`AuditLog.recent` called `readFileSync` with no position and copied the last megabyte out of the whole buffer, so a large log was held in memory in full. It now uses `openSync`, `readSync` with a position, and `closeSync`.

### R2-1. The replacement delete sentence was also an absolute

The round-one rewrite named `delete_draft` as the only irreversible operation. `send_draft` and `send_message` are irreversible too, and both are registered under `GMAIL_ALLOW_SEND=true`. Both sentences now name the send tools.

### R2-2. recent_activity did not render Cc

The renderer had a branch for `to` and none for `cc`, so a Cc recipient sat in the JSONL and never reached the tool that exists to read the JSONL back. The renderer now prints `cc` and `bcc`.

### R2-3. The send dialog hid Bcc

`SendConfirmation` had no `bcc` field and `gateSend` forwarded none, so a Bcc recipient appeared in the audit line and never on the dialog the person clicks Send on. The field was added, both send paths forward it, `src/confirm.ts` renders a Bcc line, and `test/tools.test.mjs` covers it.

### R2-4. The runtime error still said "exactly"

`parseAllowSend` told the user to set the variable to exactly `true` after every copy of that claim in the documentation had been narrowed. The message now says any case.

### R2-5. The test comment named the wrong errno

The log path is `join(blocker, 'audit.jsonl')`, so `dirname()` is the blocker file itself and `mkdirSync` throws EEXIST. The comment said ENOTDIR. It now says EEXIST, measured on Node v22 as uid 0 and as uid 65534.

### R2-6. An unbalanced quote lost a recipient

`parseAddressList('"Roberts, Dan <dan@example.com>, eve@example.com')` returned one address, and eve still received the mail while appearing in neither the dialog nor the log. A header whose quotes never close now falls back to the raw comma split, so a fragment of a display name can appear in the list and no recipient is lost. The docblock states what the split understands and what it does not.

### R2-7. Wording in the GMAIL_ALLOW_SEND paragraph

The last clause in `README.md` and `.env.example` was reworded. No change of meaning.

### O-1. update_draft omits Cc and Bcc from its audit record

`create_draft`, `send_draft` and `send_message` record `to`, `cc` and `bcc`. `update_draft` recorded `to` and `subject` only, so a Cc or Bcc set through `update_draft` reached the draft and appeared in neither the audit log nor `recent_activity`, against the README's statement that the log holds the recipients for drafts and sends. `update_draft` now records `cc` and `bcc` the way its three siblings do, and both the audit line and the `recent_activity` row carry them.

### O-2. update_draft is not named as irreversible

The Scopes and Limits sections named `delete_draft` and the two send tools as the calls that cannot be undone. `users.drafts.update` replaces a draft with no recoverable prior version and no trash step, so `update_draft` belongs there. Both sentences now name it.

## Checked and found correct

No ambient-account send path exists. Every write tool carries `account` in the `required` list the running server reports, `forWrite` resolves the named account and never falls back to `session.active()`, and `resolveFrom` refuses any `from` that is not the account's own address.

Sending is off by default. With `GMAIL_ALLOW_SEND` unset the server lists 17 tools and neither send tool is among them. With it set to `true` the list is 19. With `GMAIL_SCOPE_PROFILE=readonly` the list is 12 and no tool can change a mailbox.

No credential is committed. Every blob in the repository history, 80 objects across 5 commits, was scanned for refresh tokens, OAuth client secrets, API keys, access tokens and private keys. Nothing matched. No `.env` or credential file has ever been tracked.

The tool list matches the README. The nineteen names in the Tools section are exactly the nineteen the server registers, and the required arguments match the read and write asymmetry the README describes.

The identity check cannot be skipped. `AccountRegistry.resolve` fuses the lookup and `users.getProfile` into one step and caches the promise per label, rejections included, so a mismatch disables the account for the life of the process.

A mid-call account switch cannot produce a wrong-mailbox write. `forWrite` reads `session.active()` after the resolve completes, so a switch during the call causes a refusal.

Header injection is refused. Subject, address and threading values are checked for CR and LF before the message is assembled, addresses must be bare, and both AppleScript payloads take their values through `on run argv`.

Versions agree. `package.json`, the lockfile root, and the `VERSION` constant in `src/index.ts` all read 0.2.0.

The test count in the README is exact. 73 tests, all passing, as uid 0 and as uid 65534, with nothing written outside the repository and the system temp directory. `npm ci` installs 162 packages against the lockfile, `npm run build` and `npm run typecheck` report no errors, and `npm audit --omit=dev --audit-level=high` reports 0 vulnerabilities.

`npm run popup-test` refuses on Linux and exits 1, as the README says it does.

## Not verified here

Everything that needs live Google OAuth is unverified. `npm run authorize`, `npm run accounts` end to end, and `npm run verify` each need a real client ID, a real refresh token and a reachable Gmail API, and none of the three was run. The identity check against a real `users.getProfile` response, the shape of a real Gmail error at each status branch, draft creation and deletion in a real mailbox, and the isolation of draft IDs between real mailboxes are therefore confirmed by reading and by stubs alone. The two desktop dialogs need macOS and a logged-in window server, so neither has been shown in this pass. The Gmail handlers were exercised by driving the compiled tools against stub clients, which confirms the branching, the refusals and the audit records, and says nothing about the live API.
